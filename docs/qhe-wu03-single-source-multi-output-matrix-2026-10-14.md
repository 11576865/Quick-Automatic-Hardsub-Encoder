# QHE WU-03 · 同一来源多输出方案矩阵（B21 第一段产品能力）

**日期**：2026-10-14。**理论权威**：R19《未来产品架构》P5「批次矩阵」；R24《产品定位与压缩决策》§22「批量与配方：多个独立转码/烧录/剪切任务」。**结论**：单来源多输出方案矩阵已实现并通过限定 UI / 模型验收；B21 整体未完成。

## 1. 新增用户能力，而不是新增编码器

- 在现有 QHE 媒体工作台新增可折叠「多输出方案矩阵」：针对同一已探测素材，将当前硬字幕、纯视频转码或 Stream Copy 设置冻结成多个独立 schema-v4 执行计划。
- 每个条目保存编译完成的 FFmpeg 任务合同，包括原编码器、输出流计划、尺寸、音频策略和字幕渲染顺序。后续修改主表单不会默默更改已加入矩阵的方案。
- 开始执行时对所有待处理条目先进行来源与媒体轨道签名核对、当前 ASS/字体身份检查及后端验证；通过后按顺序交给**原有的 `hooks.run`/`hooks.save`**，不新增第二套任务编译器。
- 每项生成独立的 `-variant-XX` 输出名称，每项完成真实后端 `verified` 回执和交付预算检查才保存；失败停止后续条目，已保存成品不撤销。
- 如果保存失败，保留该成品的已验证状态，并提供「重试保存」，下一次保存不重新编码。支持取消后续输出和显式清空矩阵。
- 同源边界很明确：一次矩阵仅绑定**一个当前源文件**；更换来源拒绝执行，且用户必须主动清空重建。硬字幕方案还绑定当前字幕文本和字体文件/映射。单次限制 12 个配方。
