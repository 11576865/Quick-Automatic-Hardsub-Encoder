# 手动视频处理工作区（task schema v2）

浏览器、Android APP、Windows Native 共用设置界面与任务编译器。任务通过经过验证的输出参数数组交给原生后端；输入文件、输出文件及字体路径由后端管理，不能从网页传入任意路径或 shell 命令。

## 使用

1. 选择视频。
2. 在“视频处理工作区”选择硬字幕压制、纯视频转码或无损快速剪切。
3. 硬字幕模式需在下方完成字幕分析、字体检查及真实预览。其他模式无需字幕。
4. 设置参数，点击“检查设置与执行参数”，再开始处理。
5. 等待成品验证，点击“保存成品”。

预设按钮只填入质量和编码速度；分辨率、帧率、裁切等用户设置保持当前值。手动任务不运行自动质量校准。旧自动方案仍可作为辅助使用。

## 当前开放参数

- 起止时间（秒）；无损切入点向前定位关键帧并显示实际起点。
- H.264、HEVC、AV1；Windows 可手动选已通过运行检测的 NVENC 或 CPU 编码器。
- preset、CRF/CQ、目标码率、最大码率、缓冲区。
- 恒定/可变帧率策略；精确分数帧率，例如 `24000/1001`；输出帧数上限。
- 宽高、缩放算法、裁切、旋转、方形像素、去隔行、降噪、去色带、锐化。
- 像素格式、8/10-bit、4:2:0/4:4:4（具体组合由所选编码器验证）。
- GOP、B 帧、参考帧、线程、profile、level、tune。
- NVENC multipass、lookahead、spatial/temporal AQ、AQ strength。
- 有限的 x264/x265/SVT-AV1 专用键值参数；不允许文件路径类参数。参数是否适用于某编码器由该编码器验证，不会悄悄忽略冲突。
- 音频复制/AAC/Opus/关闭；全部音轨或指定音频轨索引；每轨音频码率、声道、采样率。
- 内封软字幕、字体附件、元数据、章节保留开关。

滤镜顺序：裁切 → 去隔行 → 缩放 → 旋转 → 画面滤镜 → 字幕 → 偶数尺寸补边。截取硬字幕片段会在字幕渲染前恢复原视频时间，渲染后还原输出时间。输入端定位后，输出端丢弃切点前音频，避免复制音频保留 preroll 而视频已裁切的不同步问题。

## 平台与限制

- 输出目前统一为 MKV；仅处理第一个视频流。
- 无损快速剪切复制视频和音频压缩数据，不保证任意帧精确边界。软字幕边界需核对。
- 浏览器受 1 GiB 输入保护、WebAssembly 及成品 Blob 内存占用约束。
- Android 使用原有 foreground service、SAF/staging、进度、取消及成品导出。当前不默认启用 MediaCodec。
- Windows 明确采用用户所选编码器；失败不会静默替换为另一编码器。
- HDR/高位深源的转码仍受既有保护限制；无损剪切可用。SDR 8-bit 源可请求 10-bit 编码，此操作不会增加源素材已有的信息。
- 指定输出帧数时暂要求关闭音频，以免片长控制歧义。
- 旧章节默认移除；主动保留时应检查剪切后的章节位置。
- 原生后端必须声明 `taskSchemaVersion: 2`，旧 APP/Windows 包会提示更新，避免新设置被旧后端忽略。

## 体积预算、试压与报告（Web 0.3.0 / Android 0.4.0-native）

码率控制现在分为恒定质量 CRF/CQ、目标平均码率、目标体积。目标体积接受 MB/GB（十进制）和 MiB/GiB（二进制），默认预留 4% 给封装与码率偏差。计算为：

`视频码率 = floor(目标字节数 × (1 − 余量百分比) × 8 / 输出秒数 − 每轨音频码率 × 输出音轨数)`。

- 选择全部音轨时计入每条输出音轨；选择单轨时只计一条。
- 音频复制大小未知时不做可靠体积承诺，需改用 AAC/Opus 的明确码率或关闭音频。
- 目标体积模式拒绝保留未计量附件；软字幕和其他封装开销仍需包含在余量内。
- 不使用 `-fs`；超出预算时完整成品保留，可导出，并提示调整后的视频码率。
- 恒定质量模式不给未经试压的数值估计；试压的外推明确标作片段估计。
- 三组短片使用同一片段，质量值 ±2 或码率 ±20%，显示实际大小、耗时和整片外推；可以保存每个短片并采用其参数。浏览器播放取决于容器/编码支持；原生短片通过现有导出流程保存后观看。
- 自定义配置在本机保存，支持 JSON 导入/导出；不支持的编码器明确提示，不静默替换。预设始终可修改。
- 任务报告 JSON 包含任务参数、实际体积、时长、耗时、预算偏差与重压建议。

x264 的目标平均码率/目标体积模式可启用整片两遍编码，三端均先统计完整所选区间，再编码并带入音频。仅开放已接入验证的 x264 两遍；没有将同一机制套用到 x265、SVT-AV1 或 NVENC。NVENC `multipass` 是逐帧内部分析，与整片两遍不同。

FFmpeg 参数与像素格式通过运行时 help 检查；旧核心缺少 `-fps_mode` 时生成 `-vsync`，也可手动启用兼容选项。NVENC 的 4:2:0 10-bit 请求使用 `p010le`，空间 AQ 和时间 AQ 不能同时启用。音频编码器可用性在执行前检查。v2 原生验证器仍接受 v1 任务，但新版 UI 的手动工作区要求 v2 后端。

输出会核对音视频流数量、时长和 packet 完整性，以及显式指定的帧率、宽高和输出位深。限制总帧数要求明确指定 CFR 目标帧率；短于视频的有效音轨不会仅因提前结束被删除。预算不能保证主观画质，4% 余量也不能保证严格上限。

## 官方资料与研究取舍

- [FFmpeg 主文档](https://ffmpeg.org/ffmpeg.html)：`-fs` 超出限制后停止写入，不适合完整视频的目标体积功能；`-pass` / `-passlogfile` 用于整片两遍统计；`-pix_fmt` 不支持时可能自动回退，因此需要能力与成品检查。
- [NVIDIA FFmpeg 指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/ffmpeg-with-nvidia-gpu/index.html)：`multipass` 为逐帧内部分析，AQ 与 lookahead 影响感知质量与资源开销。
- [FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html#libvmaf)：VMAF 依赖构建时启用 libvmaf。此次没有给所有平台添加默认 VMAF 分数；各平台核心并不保证包含该依赖，而且硬字幕、缩放、裁切后的评分需要一致的参考处理链路。当前采用真实短片比较，既有字幕预览和字体诊断继续使用。

验证：`node --test src/media-task.test.mjs src/media-planning.test.mjs`；实际 FFmpeg 集成测试新增目标体积、x264 两遍、60 fps、旧帧率参数和 Opus；CI 另验证 Windows 两遍参数与成品规格、Android Kotlin 编译、桌面/手机配置与三片比较交互。
